UI/UX Design System & Desktop Architecture

Specification, Component Hierarchies & Visual Design Tokens

An exhaustive design specification for HINAKU: a personal, local-first AI assistant built for one person. Grounded in the core brand aesthetic—"A universe without light" (光なき宇宙)—this document details the 3-column collapsible desktop shell, floating interaction composer, truthful telemetry accordions, document attachment walkthrough engine, semantic memory drawers, and complete accessibility standards.

1. Brand Vision & Design Principles

HINAKU (ヒナク) is inspired by the Japanese phrase Hikari naki uchū (光なき宇宙), meaning "a universe without light". The interface is purposefully built as a deep, calm, distraction-free desktop environment that feels quiet, contemplative, and relentlessly loyal to its single owner.

Core Design Motto:

"Darkness, infinity, mystery, solitude. One name. An infinite void. No light at the end."

This identity governs atmospheric tone and typography only. It never manifests as pessimism or hesitation in replies; HINAKU responds with precision, dry wit, and decisive clarity.

Quiet, Modern Composure

Zero high-contrast glaring lines, zero promotional popups, and zero flashy animations. Surfaces follow soft neutral-dark elevations with one muted deep violet accent.

Local-First & Private

Zero external Google Fonts, CDNs, or tracking scripts. All SVGs and CSS are bundled locally on the machine. Personal memories and private documents are never sent across network boundaries.

Truthful Backend Attribution

Every message displays a clear badge indicating whether it was produced by the local GPU model, an external API, or safety guards, with complete execution latency telemetry.

Tactile Desktop Ergonomics

Designed specifically for an HP V15 laptop with full keyboard navigation (Ctrl+B, Ctrl+., Ctrl+N, Ctrl+K), global tray summon hotkey, and smooth resizability across 1280px, 960px, and 720px viewports.

5. Floating Composer & Interaction Dock

The prompt composer is engineered as a floating elevated pill (--radius-composer: 24px) positioned at the bottom of the conversation stage. It eliminates clutter while providing immediate access to model modes and attachments.

Auto-Expanding Textarea

Expands seamlessly from single-line (44px) to multi-line (up to 180px max before scroll). Submits on Enter; inserts line break on Shift + Enter.

Dual-State Action Button

Circular submit button (36px) with deep violet fill (#8b5cf6). During active streaming, dynamically transforms into a Stop Generation square (■) with immediate abort capability.

Removable Mode Chips (Think Harder & Detailed Mode)

Clicking the + button opens a lightweight action menu that toggles specialized reasoning and depth flags:

Mode Badge Display Inference Parameter Shift Behavioral Effect
Think Harder 🧠 Think num_predict: 2048, temperature: 0.2 Allocates deep token budget for complex logic, math, and code architecture problems.
Detailed Mode 📄 Detailed × num_predict: 800, detailed persona override Forces structured, comprehensive multi-paragraph explanations ending in a clear conclusion.

Privacy Mode Selector

Standard Mode

Intelligent hybrid routing. Simple conversational queries run on local bonsai-2:9b; complex reasoning may route to external API models if configured.

Local-Only Mode

Strict physical isolation. 100% of queries execute through local Ollama on the laptop's RTX 4050 GPU. Zero outbound internet traffic.

Private Mode

Confidential mode. Strictly local GPU execution. Suppresses all semantic memory extraction and excludes turns from the 6-month self-build dataset.

Auto-Private Fallback

Automated safety guard. When passwords, PINs, or sensitive identifiers are typed, the system automatically switches to Private mode and displays a persistent banner with a 1-click Undo button.

6. Conversation View & Truthful Telemetry

Every conversation turn balances visual elegance with rigorous telemetry truthfulness. User inputs and assistant outputs are visually differentiated to maintain clear conversational momentum.

Figure 2: Active Conversation View User message fold, markdown rendering, syntax code block, and telemetry accordion

Key Message Components

  • User Message Bubble: Right-aligned elevated card (--bg-raised: #2a2a2a) with rounded corners (10px). Messages exceeding 350 characters automatically fold with a subtle gradient mask and a tactile "Show more ↓" toggle.
  • Assistant Message Body: Fluid left-aligned markdown typography. Headings (###, ####) render as distinct section headers; unordered and numbered lists render with generous padding; horizontal rules (---) render as subtle dividers.
  • Syntax-Highlighted Code Blocks: Wrapped in dark pre-formatted containers (#141416) withCasdadia Code typography, a top header showing the language tag (e.g. python, bash), and a 1-click Copy button that displays "Copied!" confirmation.
  • Truthful Backend Badges: bonsai-2:9b · local openrouter · API · logged by provider ✓ verified
  • Telemetry Accordion ("Worked for X s >"): A collapsible process summary located under assistant replies. It surfaces exact execution timings (TTFT, generation latency, tokens per second, memory extraction time), while strictly suppressing raw internal reasoning scratchpads to preserve HINAKU's cool composure.
  • Message Hover Action Bar: Floating horizontal action dock appearing on message hover: Copy Text, Thumbs Up, Thumbs Down, Edit Reply (which feeds the 6-month curation engine), Retry, and Continue (for automated continuation of truncated replies).

7. Document Attachments & Walkthrough UX

Built during Phase 2 and refined in Phase 2c, the document attachment subsystem allows the owner to attach PDF, DOCX, TXT, and HTML study notes. The UI deterministically routes between overview study walkthroughs and targeted retrieval Q&A.

Figure 3: Document Attachment Drawer & Study Notes Integration Uploaded document badge, outline section counts, and structured study cards

Document Walkthrough Features

Feature UI Element / Behavior Engineering Specification
Attachment Drawer Slide-down card above composer displaying filename, size (KB), and token count. Supports drag-and-drop & file picker; validates disk headroom (file + 2 GB) before ingestion.
Outline Extraction Extracts units, topics, sessions, study aids, and exact page ranges. Stored in SQLite attachment_sections; indexed into isolated Chroma collection.
Intent Gating Evaluates query in code: overview requests trigger walkthrough; specific questions trigger hybrid retrieval. Filters out unrelated chatter (e.g. Python coding, CPUs vs GPUs) with zero false document citations.
Structure Preamble Deterministic intro card: "Your notes contain 2 units, 9 topics in Unit 1, 5 sessions in Unit 2..." Displays measured time estimate range: e.g. ~175s estimated (range 149s–201s).
Rolling Estimate Progress banner updating topic-by-topic: Explaining topic 3 of 9 (~120s remaining). Derived from rolling average of completed topics; strictly non-increasing.
Action Chips Structured button pill at the bottom of document replies: Explain the whole document → Replaces raw markdown anchor links; triggers full walkthrough on click.
Code-Level Citations Exact outline metadata note: *Based on Session 8 — Introduction to MLSecOps (pp. 8-9).* Generated strictly in code from outline records; all model-hallucinated citations are stripped.

8. Dedicated Utility Pages

HINAKU eliminates intrusive modal popups in favor of dedicated, distraction-free utility views. These views share the same left sidebar navigation and allow full inspection of the system's memory, training data, and settings.

Figure 4: Context & Semantic Memory Management View Searchable memory cards, inline editing, category tagging, and re-index controls

1. Semantic Memory Drawer

Displays all durable facts and preferences extracted about the owner. Each memory card shows the extracted text, creation timestamp, and category badge. Users can search memories with semantic similarity, edit wording inline, delete obsolete facts, or trigger an on-demand ChromaDB re-index.

2. Dataset Curation Screen

Feeds the 6-month self-build cycle. Aggregates all interaction pairs flagged with thumbs-up or owner corrections. Provides review cards where the owner can audit training pairs, delete ungrounded entries, and view readiness against the minimum fine-tuning sample threshold.

3. Model Ratings & Bake-Off

Presents real-time telemetry comparing local models (bonsai-2:9b, gemma3:4b) against API models. Displays latency distributions, upvote/downvote ratios, token generation speeds, and persona adherence scores.

4. Settings & Data Sovereignty

Configures default local model, router mode, global hotkeys, and reduced-motion toggles. Provides 1-click **Export All Data** (JSON format) and a fail-safe **Permanent Wipe** (WIPE_ALL) that clears all SQLite databases, Chroma indices, and disk caches.

9. Keybindings, Motion & Accessibility

Every feature in HINAKU is fully operable without a mouse. Micro-interactions are snappy and respect hardware efficiency and accessibility standards.

Complete Keyboard Shortcut Cheat Sheet

Shortcut Action Name Functional Description
Ctrl + N New Chat Clears conversation viewport, resets composer, and initializes a clean conversation ID.
Ctrl + K Search Chats Focuses the search filter input in the left sidebar to quickly locate past conversation titles.
Ctrl + B Toggle Sidebar Collapses or expands the left conversation history sidebar with smooth 150ms ease transition.
Ctrl + . Toggle Context Panel Slides open or closes the right-hand context drawer showing live memories and telemetry.
Ctrl + Shift + P Cycle Privacy Mode Cycles through Standard → Local-Only → Private mode with instant status indicator feedback.
Ctrl + Shift + Space Summon / Hide Global OS hotkey managed by desktop shell to summon HINAKU from the background or minimize to tray.
Esc Stop / Dismiss Immediately aborts streaming model generation; closes active dropdown menus or utility pages.
Enter Send Prompt Submits current prompt to the model router.
Shift + Enter Newline Inserts a clean line break in the expanding composer textarea without submitting.

Motion & Accessibility Engineering

Reduced Motion Compliance

Strictly observes the OS-level prefers-reduced-motion: reduce media query. When enabled, all CSS transitions collapse from 150ms/250ms to 0ms, and the subtle ambient star-field canvas is completely disabled to prevent disorientation.

Screen Reader & Focus Rings

All interactive controls feature a prominent outline: 2px solid var(--accent-hinaku) focus state. Streaming assistant responses emit into an aria-live="polite" region so screen readers receive updates without interruption.
